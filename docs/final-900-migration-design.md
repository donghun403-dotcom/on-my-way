# 마지막 900 정리 설계 — 사문을 지우고 래칫을 계약으로 올린다

`styles.css`에 `font-weight: 900`이 90개 남아 있다(PR #58 이후). 이 설계는 그것을
**전부** 처리해 굵기 이관 작업을 끝낸다. 남는 900은 글리프 캐리어 11곳뿐이다.

## 먼저 정정 — 지난 라운드의 버킷은 느슨했다

PR #58은 남은 90곳을 "랜딩·온보딩 40 · 관리자 9 · 글리프 10 · script.js 생성 또는
사문 후보 30 · 앱 글리프 1"로 넘겼다. 그 분류는 **셀렉터 안의 아무 클래스나 걸리면 그
화면으로 넣는** 방식이었다. `.home-page .pillar-number`는 `home-page`가 index.html에
있다는 이유로 랜딩에 들어갔지만, 정작 `pillar-number`는 저장소 어디에도 없다.

**가장 구체적인 클래스(셀렉터 조각의 마지막 클래스)**를 기준으로 다시 가르면:

| 버킷 | 수 | 판정 근거 |
| --- | --- | --- |
| 랜딩 (index.html 렌더) | 22 | 클래스가 index.html에 실재 |
| 관리자 (admin.html) | 9 | 클래스가 admin.html에 실재 |
| script.js가 생성 | 2 | `row.className = "task-builder-item"` 등 실제 생성 코드 |
| 글리프 캐리어 | 11 | `content`가 문자 아이콘이거나 `×`·`✓` 캐리어 |
| **사문** | **46** | 저장소 전체에 클래스 문자열이 없다 |

앱 표면은 #58에서 닫힌 것이 맞다. `.execution-page .calendar-day-detail-list i`는
`::before`가 아닌 `<i>` 엘리먼트라 버킷 이름만 달랐을 뿐, #55에서 이미 "✓" 글리프로
주석까지 달아 유지 처리한 선언이다. 글리프 총계가 10이 아니라 11인 이유다.

## 사문 46곳 — 삭제한다

지난 두 라운드는 "사문으로 판정된 선언도 배정대로 이관한다, 삭제는 별도 판단"으로
미뤄 왔다. 이번이 그 별도 판단이고, 결론은 **삭제**다.

근거: 아무것도 렌더하지 않는 선언에 역할 토큰을 주는 것은 이관이 아니라 연출이다.
래칫이 헛수를 지키게 되고, 다음 사람이 그 규칙을 살아있는 코드로 읽는다.

사문 클래스가 거느린 CSS는 **규칙 210개 · 1333줄**로, `styles.css` 19,259줄의 6.9%다.
900 한 줄만 지우고 나머지를 남기면 절반만 죽은 규칙이 되므로 **규칙째 지운다.**

**콤마 오염은 0건이다.** 210개 규칙 중 살아있는 셀렉터와 콤마로 묶인 것은 하나도
없다. 셀렉터 조각별로 확인했다.

### 사문 판정의 자기 검증

"사문"은 문자열 검색의 결론이므로 검색이 틀릴 수 있는 경로를 각각 막았다.

| 오판 경로 | 확인한 것 | 결과 |
| --- | --- | --- |
| 검색 범위가 좁다 | 저장소 전체 `.html`/`.js`/`.cjs`/`.mjs` 순회 | 46곳 전부 무참조 |
| 백업 스냅샷을 살아있는 코드로 셈 | `.backups/onboarding-v*-20260727/`는 추적되지 않는 로컬 스냅샷 | 제외 |
| 클래스를 동적으로 조립 (`'pillar-' + k`) | 접두사 조립 흔적 검색 | 후보 3건 전부 `plan-${Date.now()}` 류 **ID 생성기**, 클래스 아님 |
| 프로토타입이 쓴다 | `.goal-form`은 `core-loop-v2.html`에만 있으나 그 페이지는 `core-loop-v2.css`를 로드 | styles.css 규칙은 사문 |

## 삭제 안전 증명 — 계산값 전수 diff

스크린샷 육안 비교는 1333줄 삭제의 증거로 약하다. 미묘한 여백·색 변화를 놓친다.

`scripts/snapshot-computed-styles.cjs`를 만들어 **커밋한다.** 랜딩·관리자·앱을 열고
모든 엘리먼트를 순회하며 DOM 인덱스 경로를 키로 computed style 한 묶음을 JSON으로
떨군다. 삭제 전후를 비교해 **diff가 0**이어야 커밋한다.

- **키**: `body>div:nth-child(2)>section:nth-child(1)` 형태의 DOM 인덱스 경로. CSS만
  지우면 DOM은 변하지 않으므로 안정적이다.
- **값**: `font-weight` · `font-size` · `font-family` · `color` · `background-color` ·
  `padding` · `margin` · `border-radius` · `box-shadow` · `display`
- **판정**: 차이 나는 키가 하나라도 있으면 그 엘리먼트에서 어떤 셀렉터가 죽었는지
  역추적한다. 사문 판정이 틀린 것이므로 그 클래스를 삭제 목록에서 뺀다.

**커밋하는 이유**: `admin.html`에는 e2e 스펙이 아예 없다. 관리자 화면의 안전망은 이
스냅샷뿐이다. 그리고 #55에서 측정 스크립트를 커밋하지 않아 다음 라운드에서 근거를
잃은 전례가 있다.

## 이관 33곳 — #55·#58과 같은 방법

1. **분류표를 먼저 산출물로 만든다** (`docs/artifacts/final-900-classification.md`).
   행마다 실제 마크업(`index.html`·`admin.html`·`script.js`)을 근거로 배정한다.
   셀렉터 이름만 보고 판정하지 않는다.
2. 화면 단위(랜딩 / 관리자+script)로 나눠 **이관 → 유닛 → 실측 diff → e2e**를 돌고
   커밋한다.
3. 배정은 기존 4단계 역할 토큰만 쓴다. `--weight-emphasis`의 정의는 #58에서 "본문
   성격의 강조"까지 넓혔고, 이번에 더 넓힐 일은 없다.

**굵기를 판단할 때는 선언이 아니라 렌더된 값을 본다.** #58에서 `.card-title span` 등
3곳이 캐스케이드에서 지고 있어 셀렉터만 봤으면 오판했을 곳이었다.

## 래칫을 계약으로 올린다

`fonts.test.mjs`의 잔여 수 래칫은 세 라운드 동안 숫자를 203 → 139 → 90으로 내렸을
뿐이다. 이관이 끝나면 지킬 숫자가 없다. 남는 900은 전부 글리프 캐리어이므로 숫자
대신 **규칙**을 지킬 수 있다.

```js
test("남은 font-weight:900은 전부 글리프 캐리어 — 사유 주석을 요구한다", () => {
  const lines = fs.readFileSync("styles.css", "utf8").split("\n");
  const offenders = [];
  lines.forEach((line, i) => {
    if (!/font-weight:\s*900\b/.test(line)) return;
    if (!/글리프 굵기/.test(lines.slice(Math.max(0, i - 4), i).join("\n"))) {
      offenders.push(i + 1);
    }
  });
  assert.deepEqual(offenders, []);
});
```

새 900이 들어오면 사유 주석이 없어서 걸리고, 실패 메시지가 **줄 번호를 지목**한다.
숫자 assert는 지운다 — 이 테스트가 포함한다. 주석을 위조하면 통과하지만, 그러려면
"이건 글리프다"라고 명시적으로 거짓말을 해야 한다. 실수로는 통과할 수 없다.
