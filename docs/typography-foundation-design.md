# 타이포그래피 기반 재설계 — 잘난체 제거와 Pretendard 전면 적용

- 작성일: 2026-07-30 (KST)
- 브랜치: `feat/ui-ux`
- 기준 커밋: `abcade5` (이 문서의 모든 줄 번호는 이 커밋 기준)
- 단계: **C** — UI/UX 개선 3단계(C 타이포 → A 온보딩 → B 앱 내부) 중 첫 번째

## 배경

유저 피드백에 "폰트가 눈에 들어오지 않는다"가 있었다. 원인을 찾아보니 서체 취향
문제가 아니었다.

`styles.css`의 `--font-body`는 `"Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", sans-serif`를
가리키는데, **`Pretendard`를 로드하는 `@font-face`가 저장소 어디에도 없다.**
`@font-face`는 `여기어때 잘난체` 하나뿐이고(`styles.css:1-5`),
`assets/fonts/`에도 `yeogieottae-jalnan2.woff2` 한 개만 있다.

그래서 본문 전체가 조용히 OS 기본 한글 글꼴로 떨어진다. iOS는 Apple SD Gothic Neo,
Windows는 맑은 고딕이다. 이 글꼴들은 굵기 단계가 좁아서 400과 합성 볼드 두 단계로
뭉개진다. `styles.css`에 있는 **533개의 `font-weight` 선언 중 상당수가 화면에서
서로 구분되지 않는다.** "무엇이 중요한지 안 보인다"의 실체가 이것이다.

### 이 버그가 이미 한 번 "고쳐졌던" 이유

`docs/design-tokens.md:25-31`에 같은 증상의 기록이 있다. `.execution-page` 블록이
`--font-body: 15px`를 선언해 전역의 *패밀리* 토큰을 덮어썼고, 그 결과
`body { font-family: var(--font-body) }`가 `font-family: 15px`가 되어 무효 처리되면서
앱 텍스트 146개 요소가 OS 기본 글꼴로 렌더링됐다. 이 충돌은 수정됐고 회귀 테스트도
붙었다(`design-tokens.md:161-164`).

**그 수정은 토큰 충돌만 풀었고, 폰트 파일이 없다는 사실은 건드리지 않았다.**
토큰이 올바르게 `Pretendard`를 가리켜도 로드된 적이 없으므로 렌더 결과는 그대로
OS 기본 글꼴이다. 문서에 "이제 Pretendard로 렌더링된다"는 취지로 적혀 있지만
실제로는 아니다.

기존 테스트가 이걸 못 잡은 이유는 명확하다. `tests/e2e/core-loop-v2.spec.js:16-34`는
**잘난체에 대해서는** 실제 woff2 응답을 기다려 200과 `content-type`을 확인하고
`data-brand-font-state="loaded"`와 `document.fonts.check`까지 단언한다(:18-26).
그런데 본문 폰트에 대해서는 `getComputedStyle(...).fontFamily` **문자열만** 본다(:31).
선언된 이름이 맞는지만 보고 그 폰트가 실재하는지는 보지 않는다.
`core-loop-v2.test.mjs:24`도 `--font-body` 토큰의 문자열을 정규식으로 맞춰볼 뿐이다.

→ **이번 설계의 재발 방지책은 잘난체에 이미 쓰고 있는 검증을 본문 폰트에도
그대로 복제하는 것이다.** 새 패턴을 발명할 필요가 없다.

## 결정

1. **잘난체를 완전히 제거하고 Pretendard 한 가족으로 통일한다.** (제품 오너 결정)
   제목과 본문의 구분은 이제 *글꼴 가족*이 아니라 *굵기*가 담당한다.
2. 접근은 **"교체 + 굵기 역할 토큰화"**. 533개를 전부 재조판하지 않고,
   토큰을 세운 뒤 필요한 지점만 이관한다.

후보 비교(Pretendard / SUIT / Gothic A1 / 고운돋움+Pretendard)를 실제 앱 문구로
렌더링해 검토했고 Pretendard로 정했다. 고운돋움은 굵기가 400 하나뿐이라
"굵기 단계 부재"라는 이번 문제를 제목에서 그대로 재현하므로 후보에서 탈락했다.

고치는 것은 B다.

## 설계 1 — 폰트 자산과 로딩

### 넣을 것

`Pretendard Variable` dynamic subset을 `assets/fonts/pretendard/`에 넣는다.

- woff2 **92개**, 합계 **2.82MB**
- 브라우저는 화면에 뜬 글자의 `unicode-range`에 해당하는 조각만 내려받는다

저장소가 이미 `assets/`에 6.1MB를 담고 있고 단일 PNG가 최대 1.4MB이므로
(`assets/og-ollie-share-v1.png`) 2.82MB는 이 저장소에서 이례적인 크기가 아니다.

**단일 파일 방식을 쓰지 않는 이유**: 한글 전체가 든 파일은 매번 1MB 이상을 통째로
받는다. **글리프를 미리 추려 넣는 방식을 쓰지 않는 이유**: AI가 생성하는 계획 문구는
임의의 한글이 나올 수 있어서, 빠진 글자만 폴백 글꼴로 튀면 그게 더 눈에 띈다.

### 뺄 것

- `assets/fonts/yeogieottae-jalnan2.woff2` (414KB)
- `styles.css:1-5`의 `@font-face`
- `styles.css`의 `여기어때 잘난체` 직접 참조 3곳

워드마크는 `assets/logo-horizontal-ollie.png`로 **이미지**다(`app.html:38`).
글꼴을 빼도 로고는 변하지 않는다.

### 로딩

- `font-display: swap` 유지. 글자가 먼저 보이는 편이 낫다.
- **preload는 실측 후 결정한다.** dynamic subset은 어떤 조각이 필요한지 미리 알 수
  없다. 첫 화면을 띄워 실제로 요청되는 subset을 관찰한 뒤 상위 1~2개만 preload한다.
  추측으로 넣으면 쓰지 않는 파일을 받게 된다. 현재 폰트 preload는 없다
  (`app.html:33`은 `ollie-action.png`만 preload).
- 잘난체에 쓰던 실패 감지(`data-brand-font-state`)를 본문 폰트 기준으로 옮긴다.

## 설계 2 — 토큰

```css
/* 가족: 하나로 통일. 이름은 유지해 호출부 24곳의 셀렉터를 건드리지 않는다. */
--font-body:  "Pretendard Variable", "Pretendard", -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif;
--font-numeric: var(--font-body);       /* 사용처에서 font-variant-numeric: tabular-nums */
--font-brand-display: var(--font-body); /* 제목은 이제 가족이 아니라 굵기로 구분한다 */
--font-brand-ui:      var(--font-body);

/* 굵기 역할 토큰 (신설) */
--weight-body:     400;
--weight-emphasis: 600;
--weight-title:    700;
--weight-display:  800;
```

### 굵기 값이 400/600/700/800인 이유

`docs/design-tokens.md:93-95`가 **font-weight는 400/500/600/700/800/900 6단계만**
쓰도록 정하고 있다. 이전에 있던 650·730·750·850·950은 폴백 글꼴에 실제로 존재하지
않아 굵게로 스냅되는 무의미한 변주였고, 그래서 정리됐다.

역할 토큰은 이 6단계 **안에서만** 값을 고른다. 450 같은 중간값은 Pretendard 가변
폰트에서는 렌더링되지만, 그 정리를 되돌리는 셈이라 쓰지 않는다. 500과 900은 스케일에
남아 있으니 개별 지점에서 필요하면 직접 쓸 수 있다.

굵기를 400/600/700/800으로 잡아도 목적은 달성된다. 지금 이 네 단계가 구분되지 않는
이유는 값이 촘촘해서가 아니라 **글꼴에 그 굵기가 없어서**다. 가변 폰트가 깔리면
네 단계는 처음으로 서로 다르게 렌더링된다.

### 이름 규칙

`design-tokens.md:89`의 **"`--font-*`는 글꼴 패밀리, `--text-*`는 크기"** 규칙을
그대로 따른다. 굵기는 세 번째 축이므로 `--weight-*`로 별도 접두사를 쓴다.
세 축을 섞지 않는다.

## 설계 3 — brand 계열 24곳 이관

`font-family: var(--font-brand-display | --font-brand-ui)` 선언은 24곳이다.
가족만 갈아끼우면 안 되는 이유가 여기 있다.

| 현재 상태 | 개수 | 처리 |
| --- | --- | --- |
| `font-weight: 400`으로 고정 | **8** | `--weight-title` 또는 `--weight-display`로 교체 (아래 판단 기준) |
| 400 외 굵기 지정 (600·700) | 6 | 해당 역할 토큰으로 치환. 렌더 결과는 사실상 동일 |
| 굵기 미지정 (상속) | 10 | 상속값을 실측하고, 애매하면 명시 |

**8곳을 반드시 처리해야 하는 이유**: 잘난체는 실제 굵기가 400 하나뿐이라
(`design-tokens.md`의 폰트 조사, `font-synthesis: none`) 제목 규칙들이 400으로
못박혀 있다. 가족만 Pretendard로 바꾸고 굵기를 두면 **이 제목들이 지금보다
얇아진다.** 개선하려다 악화시키는 지점이다.

해당 8곳 (`styles.css` 기준): `249`, `14743`, `14781`, `14893`, `14923`, `15101`,
`17796`, `18093`.

**어느 토큰으로 보낼지의 판단 기준** — 화면에서 그 요소가 맡은 역할로 정한다.
줄 번호만 보고 정하지 않고, 실제 렌더링된 화면에서 확인한다.

| 역할 | 토큰 |
| --- | --- |
| 화면 제목(H1급), 큰 숫자, 주요 CTA | `--weight-display` (800) |
| 섹션·카드 제목 | `--weight-title` (700) |
| 라벨·메타·칩·탭처럼 짧은 UI 문구 | `--weight-emphasis` (600) |

## 설계 4 — 그 외 적용 범위를 정하는 방법

533개를 전부 건드리지 않는다. 위 24곳과 하드코딩 4곳 외에는,
**지적된 4개 화면에 실제로 렌더링되는 타이포 역할만** 이관한다.

캡쳐 6장에 담긴 지적 7건은 화면 4개로 모인다.

1. 온보딩 — 조건 입력 (`index.html`, 목표 기간·시간대·요일·스타일·가능 시간)
2. 온보딩 — 1차 계획 보기 (`index.html`, 로드맵·첫 7일 미리보기·CTA·자세히 보기)
3. 앱 — 오늘 탭 (`app.html`)
4. 앱 — 계획 탭 (`app.html`)

"실제로 렌더링되는"을 추측으로 정하면 안 쓰는 규칙을 건드리고 정작 화면에 뜨는 것을
놓친다. 그래서 **로컬 서버(8766)에 이 4개 화면을 띄우고 텍스트 노드를 순회해 실제
적용 중인 `(font-size, font-weight)` 조합을 수집**한 뒤, 그 집합만 토큰에 붙인다.

나머지 약 500개 선언은 값을 그대로 둔다. 글꼴만 바뀌므로 굵기 단계는 저절로 살아난다.

### 하드코딩 4곳

`styles.css`에 `-apple-system, BlinkMacSystemFont, …` 스택을 직접 쓴 곳이 4개 있다.
여기는 토큰을 우회하므로 **고치지 않으면 Pretendard가 아예 적용되지 않는다.**
전부 `var(--font-body)`로 바꾼다.

## 테스트

### 갱신

`core-loop-v2.test.mjs`와 `tests/e2e/core-loop-v2.spec.js`에 잘난체를 전제한 단언이
합쳐서 25개 있다. 전부 갱신한다.

### 신설

**1. 선언과 실물의 일치 (핵심)**

잘난체에 이미 적용된 검증(`tests/e2e/core-loop-v2.spec.js:18-26`)을 본문 폰트에
복제한다.

- 유닛: `styles.css`의 모든 `@font-face` `src` 경로가 실제 파일로 존재하는지
- e2e: Pretendard subset woff2 응답을 기다려 `200`과 `font/woff2` 확인
- e2e: `document.fonts.check`로 실로드 확인. **단, `check()`만으로는 부족하다** —
  폰트 로딩 중에는 `false`를 돌려주므로 `document.fonts.ready`를 기다린 뒤 확인하고,
  같은 문자열을 폴백 글꼴로 렌더링한 폭과 **비교해 다른지까지** 본다.
  (이번 조사에서 이 방법으로 잘난체가 실제로는 적용되지 않은 상태를 잡아냈다.
  `check()` 결과만 믿었다면 로딩 중 상태를 실패로 오판할 뻔했다.)

**2. 굵기 회귀 가드** — 위 8곳이 `400`으로 되돌아가지 않게 단언한다.

**3. 잘난체 잔존 0** — 저장소 전체(`*.mjs|js|cjs|html|css`)에서 `여기어때 잘난체`와
`Jalnan` 참조가 하나도 없음을 단언한다. `plan-policy.test.mjs`의
"`PLAN_CONFIG.free` 참조가 소스에 하나도 없다"와 같은 관용구를 따른다.

## 검증

- `npm test` — 이 worktree의 기준선은 **443 pass / 0 fail** (측정 완료)
- e2e — **반드시 `E2E_BASE_URL=http://127.0.0.1:8766`을 넘긴다.**
  기준 커밋의 `playwright.config.js`는 `baseURL`이 `127.0.0.1:8765`로 하드코딩돼
  있고 `reuseExistingServer`가 로컬에서 켜져 있다(:16, :26-27). 넘기지 않으면
  8765에 떠 있는 다른 worktree의 서버를 붙잡아 남의 파일을 테스트한다.
  (이 하드코딩을 없애는 수정이 별도로 진행 중이며, main에 들어오면 rebase 후
  이 제약은 사라진다.)
- 320 / 390 / 430 / 1440 폭에서 위 4개 화면 스크린샷.
  533개가 한꺼번에 진짜 굵기가 되므로 **범위와 무관하게 눈으로 훑는다.**
- 실측 기록: 첫 화면이 실제로 내려받는 subset 개수와 총 바이트.
  preload 대상을 여기서 정하고, 이후 회귀를 재는 기준으로 쓴다.

## `docs/design-tokens.md` 개정

이 작업은 그 문서에 적힌 계약 두 개를 바꾼다. 문서를 함께 고친다.

1. **:112** — "여기어때 잘난체는 대표 제목·CTA·탭·칩에만. 본문·입력·숫자는 `--font-body`."
   → 잘난체가 사라지므로 이 계약을 제거하고, "글꼴은 한 가족이며 제목과 본문은
   굵기로 구분한다"로 대체한다.
2. **:93-95** — 6단계 굵기 규칙은 유지하되, 그 근거였던 "폴백 글꼴에 존재하지 않는
   굵기"라는 전제가 바뀌었음을 명시한다. 가변 폰트가 깔리면 6단계가 모두 실제로
   렌더링된다.
3. **:25-31** — 이 절이 서술하는 수정은 토큰 충돌만 해결했고 글꼴은 여전히 로드되지
   않았다는 사실을 덧붙인다. 같은 오해가 반복되지 않게 한다.

## 위험과 되돌리기

- **최대 위험**: 533개 굵기가 동시에 실재화되면서 의도치 않은 곳의 위계가 바뀐다.
  범위를 좁혀도 이 효과는 전역이므로, 위 스크린샷 확인이 형식적 절차가 아니다.
- **되돌리기**: 폰트 파일 추가와 토큰·선언 변경이 전부라 커밋을 되돌리면 원상 복구된다.
  마이그레이션도 서버 변경도 없다.
- 백엔드·API·결제·인증·배포에는 영향이 없다.
