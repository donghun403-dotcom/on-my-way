# Ollie 디자인 토큰

`styles.css` 최상단 `:root` 블록이 **유일한 색·형태 정의 지점**입니다.
새 값을 하드코딩하지 말고 여기 있는 토큰을 쓰세요.

## 왜 정리했나

이전에는 서로 모순되는 토큰 세트가 **7개** 공존했습니다.

| 블록 | 선택자 | 문제 |
|---|---|---|
| `--blue/--ink/--muted` | `:root` | 기본 세트 |
| `--admin-*` | `.admin-page` | 별도 팔레트 |
| `--app-*` (다크) | `.home-page`, `.execution-page` | **같은 내용이 2번** 정의된 폐기된 다크 테마 |
| `--routine-*` | `.home-page, .execution-page` | 세 번째 팔레트 |
| `--soft-*` | `.execution-page` | 네 번째 팔레트 |
| `--app-ink/--app-mint` | `.execution-page` | 위 `--app-*`와 **같은 선택자에 모순된 값** |
| `--pricing-*` | `.pricing-v2` | 다섯 번째 팔레트 |

결과적으로 하드코딩된 색이 **827종**이었고, 그중 파랑 계열만 353종이었습니다.
(파랑 353 / 세이지·틸 175 / 니어화이트 123 …)

### 실제로 깨져 있던 것

1. **앱 전체 폰트가 의도한 폰트가 아니었음**
   `.execution-page` 블록이 `--font-body: 15px`를 선언했는데, 이 이름은 전역에서
   *font-family* 토큰이었습니다. `<body class="execution-page">`이므로
   `body { font-family: var(--font-body) }`가 `font-family: 15px`가 되어
   무효 처리(invalid at computed-value time)되고, `<html>`의 기본 글꼴을 상속했습니다.
   → 앱의 텍스트 146개 요소가 Pretendard가 아니라 **OS 기본 한글 글꼴**로 렌더링.
   기기마다 다르게 보였습니다. (Windows: Noto Sans KR / Malgun, macOS: Apple SD Gothic Neo)

   **이 항목이 서술하는 수정은 토큰 충돌만 없앴습니다.** `.execution-page`의
   `--font-body: 15px` 재선언을 지워 `font-family: var(--font-body)`를 다시 유효한
   선언으로 되돌렸을 뿐, 그 시점 저장소에는 `--font-body`가 가리키는 이름(`Pretendard`)을
   실제로 로드하는 `@font-face`가 **없었습니다.** 그래서 이 수정 뒤에도 렌더 결과는
   바뀌지 않고 계속 OS 기본 한글 글꼴이었습니다 — 이름은 맞는데 실체가 없는 상태였습니다.
   `--font-body` 토큰의 문자열만 비교하는 테스트는 이 상태를 통과시킵니다. 지금은
   Pretendard Variable을 self-host해 실제 파일이 있습니다.

2. **대비 미달** — 하단 탭 라벨 2.54:1, 보조 텍스트 2.39~3.06:1 (AA 기준 4.5:1)

3. **형태 무질서** — 한 화면에 border-radius 17종, box-shadow 10종

## 구조

**primitive → semantic → 별칭** 3단계입니다. 컴포넌트에서는 semantic만 쓰세요.

### primitive 램프

- `--blue-50 … --blue-900` — 클라우드 블루 (주색)
- `--lilac-50 … --lilac-700` — 라일락 (그라데이션 파트너)
- `--blush-50 … --blush-600` — 블러시 (따뜻한 강조)
- `--mint-50 … --mint-600` — 민트 (**성장·완료·성공 전용**)
- `--n-0 … --n-900` — 쿨 뉴트럴
- `--amber-*`, `--rose-*` — 경고 / 위험

### semantic 역할

| 토큰 | 값 | 흰 배경 대비 |
|---|---|---|
| `--ink` | blue-900 | 11.50:1 |
| `--ink-secondary` | n-700 | 7.97:1 |
| `--ink-muted` | n-600 | 5.57:1 |
| `--ink-subtle` | n-500 | 3.80:1 — **큰 텍스트·장식 전용** |
| `--ink-brand` | blue-700 | 6.13:1 |
| `--ink-on-brand` | blue-900 | 4.63:1 (브랜드 그라데이션 위) |

표면은 `--surface`, `--surface-sunken`, `--surface-brand-soft` …
테두리는 `--border-subtle`, `--border-default`, `--border-strong`.

### 브랜드

```css
--brand-gradient: linear-gradient(135deg, var(--blue-400), var(--lilac-400));
--brand-solid: var(--blue-700);
```

> **주의 — 브랜드 그라데이션 위에는 흰 글씨를 쓰지 마세요.**
> 파스텔이라 흰색은 밝은 쪽 끝에서 2.06:1까지 떨어집니다.
> `--ink-on-brand`(네이비)를 쓰면 그라데이션 전 구간에서 4.63:1 이상을 유지합니다.
> 흰 글씨가 꼭 필요하면 `--brand-gradient-strong` 또는 `--brand-solid`를 쓰세요.

### 형태

- radius: `--r-xs`(8) `--r-sm`(12) `--r-md`(16) `--r-lg`(20) `--r-xl`(26) `--r-pill` `--r-circle`
  - 비대칭 radius(`50% 50% var(--r-md) var(--r-md)` 같은)는 올리의 유기적인 느낌이라 유지합니다.
- shadow: `--shadow-xs/sm/md/lg/xl` — 전부 네이비 틴트 `rgba(30,58,95,α)`
- space: `--space-1`(4) … `--space-16`(64)
  - **간격은 일부만 토큰화되어 있습니다.** 스케일 사이에 끼어 있던 드문 값
    (13·15·17·18·19·22·26·27·30px, 201개 선언)만 스냅했고,
    자주 쓰이는 값(2·5·6·7·9·10·11·14px)은 **일부러 그대로 뒀습니다**.
    간격은 색과 달리 하중을 받습니다 — 9px gap이 320px에서 칩 3개를 들어가게
    만드는 값일 수 있는데, E2E는 오버플로는 잡아도 "답답해 보임"은 못 잡습니다.
    새로 만들 때는 `--space-*`를 쓰되, 기존 값을 일괄 변환하지는 마세요.
- type size: `--text-display/h1/h2/h3/lg/md/sm/xs/2xs`
  - **`--font-*`는 글꼴 패밀리, `--text-*`는 크기입니다.** 다시 섞지 마세요.
  - `--text-2xs`(11px)가 **최소 가독 크기**입니다. 이보다 작은 값을 만들지 마세요.
    한글은 라틴보다 자소 밀도가 높아 8~9px에서는 사실상 읽히지 않습니다.
    (iOS caption2 = 11pt, Material 최소 라벨 = 11sp)
- font-weight: `400 / 500 / 600 / 700 / 800 / 900` 6단계만 씁니다.
  이전에 있던 650·730·750·850·950은 본문 폴백 글꼴(맑은 고딕, Apple SD Gothic Neo)에
  실제로 존재하지 않는 굵기라 어차피 굵게로 스냅됩니다 — 의미 없는 변주였습니다.
  - **이 "어차피 스냅된다"는 근거는 이제 유효하지 않습니다.** Pretendard Variable은
    가변 글꼴이라 750을 750으로 그립니다. 중간값은 눈에 안 띄는 무의미한 변주가 아니라
    **눈에 보이는 계약 위반**이 됐습니다. 지켜야 하는 이유가 "어차피 같아서"에서
    "굵기 단계를 셀 수 있게 유지하려고"로 바뀐 것이지, 계약이 느슨해진 게 아닙니다.
  - 적용 범위는 `styles.css`와 `legal.css` **둘 다**입니다. 법적 고지 4개 페이지는
    `styles.css`를 링크하지 않는 독립 파일이라(→ `pretendard-variable.css` + `legal.css`)
    `--weight-*` 토큰을 쓸 수 없습니다. 리터럴로 적되 6단계 안에서 고르세요.
    `fonts.test.mjs`의 "font-weight는 6단계 계약 안의 값만 쓴다"가 두 파일을 다 훑습니다.

### `--weight-*` 축

제목과 본문은 이제 글꼴 가족이 아니라 **굵기**로 구분합니다. 6단계 굵기 계약 안에서,
그중 네 값에 역할 이름을 붙인 것이 이 축입니다.

| 토큰 | 값 | 역할 |
|---|---|---|
| `--weight-body` | 400 | 본문 기본값 |
| `--weight-emphasis` | 600 | 라벨·메타·칩·탭처럼 짧은 UI 문구 |
| `--weight-title` | 700 | 섹션·카드 제목 |
| `--weight-display` | 800 | 화면 제목(H1급)·큰 숫자·주요 CTA |

900은 이 축에 들어 있지 않습니다. `styles.css`의 `font-weight: 900` 선언은 **139개**
남았습니다(원래 237 → 4개 화면 실측 이관으로 203 → `.execution-page` 계열 66곳 전수
처리로 139). 실행 화면 66곳의 분류 근거와 배정은
`docs/artifacts/execution-900-classification.md`에 있습니다 — emphasis 56 · title 5 ·
display 3, 그리고 **글리프 캐리어 2곳**("✓"를 그리는 `.execution-check::after`와
`.calendar-day-detail-list i`)은 텍스트 위계가 아니라 900 리터럴 + 사유 주석으로
남겼습니다. 남은 137개는 **의도적으로 고른 값이 아닙니다.** 이전 폴백 글꼴(맑은 고딕,
Apple SD Gothic Neo)에서는 700·800·900이 전부 같은 합성 볼드로 렌더링돼 구분이 없었고,
그래서 900을 그대로 둬도 눈에 띄지 않았습니다. Pretendard Variable 아래에서는 이 900들도
실제로 다르게 렌더링되므로, 화면에 나타날 때마다 위 표를 기준으로 재판단이 필요합니다.
분포는 랜딩·온보딩(`.home-page`) 27, 결제·체험·가격 9, 다이어리 북 샘플 4, 관리자 7,
그 외 롱테일이며 후속 단계가 이어받습니다. `fonts.test.mjs`의 **잔여 수 래칫 테스트**가
139를 고정하고 있어 새 900은 조용히 들어올 수 없습니다 — 이관을 이어가면 그 수를
내리고, 새 900이 정당하면 분류표에 근거를 남기세요.

이 표는 UI 요소(제목·라벨·칩·탭)만 상정합니다. **본문 성격의 강조는 다루지 않습니다.**
`.ollie-message p` / `.ollie-chat-preview p`(올리 말풍선 본문)와 `.app-toast`가 이 표
어디에도 맞지 않아 `--weight-title`(700)에 판단 보류로 남아 있습니다. 표를 늘릴지 이
둘을 재배치할지는 A·B 단계의 결정입니다.

## 조심할 것 — 폼 안의 포괄 버튼 규칙

`.home-page .personality-form button`이 **폼 안의 모든 버튼**에
`--brand-gradient-strong` + 흰 글씨를 칠하고 있었습니다. (0,3,0)이라
`.goal-suggestions button`(0,2,0)을 이겨서, 목표 카테고리 칩 7개와
빠른 조건 칩이 전부 진한 그라데이션 블록으로 렌더링됐습니다.
결과적으로 한 화면에 Primary CTA처럼 보이는 요소가 8개가 되어
"화면당 Primary CTA 하나" 계약이 깨져 있었습니다.

칩은 `.home-page .personality-form .goal-suggestions button`(0,4,0)으로
되돌렸습니다. **폼 안에 새 컨트롤을 넣을 때는 이 포괄 규칙을 먼저 확인하세요.**
버튼처럼 생기지 않아야 하는 컨트롤은 스코프를 한 단계 더 좁혀야 합니다.

## 유지되는 계약

- 글꼴은 Pretendard 한 가족입니다. 제목과 본문은 가족이 아니라 `--weight-*`로 구분합니다.
- 서드파티 브랜드 색(`#fee500` 카카오, `#03c75a` 네이버)은 토큰화하지 않습니다.
- 민트는 성장/완료 의미에만. 일반 UI에 쓰지 마세요.

## 탭 타깃

모든 독립 컨트롤은 **44×44**를 만족합니다. (프로젝트가 이미 시트 닫기·수정
버튼에 대해 `plan.spec.js`, `today.spec.js`에서 44를 단언하고 있어 같은 기준을
나머지에도 적용했습니다.)

> 글꼴 가족을 바꾸면 글자 폭이 바뀝니다. 히트 영역이 글자 폭을 따라가는 컨트롤은
> 그때 44px 밑으로 내려갈 수 있습니다. 실제로 Pretendard 전환에서 푸터 법적 링크가
> 44 → 38.03px로 내려갔고 `tap-targets.spec.js` 8건이 깨졌습니다. `::after` 오버레이에
> `min-width: 44px`를 넣어 글자 폭과 무관하게 만들었습니다.
> **글꼴을 바꾸는 작업은 이 테스트를 반드시 돌리세요.**

시각적으로 작아야 하는 컨트롤은 **모양을 바꾸지 않고 히트 영역만** 넓혔습니다.

| 컨트롤 | 방식 |
|---|---|
| 시트 닫기(34px 원), 헤더 로고·햄버거, 푸터 법적 링크 | 투명 `::after` 오버레이 |
| 할 일 체크박스 | 30px → **44px 실제 크기** + task-row 그리드 열 30→44 |
| 나머지 버튼·입력·summary | `min-height: 44px` |

체크박스는 처음에 투명 border로 히트 영역만 넓히려 했지만, 이 input에
겹치는 규칙이 4개(그중 2개는 ID 스코프)라 원형에 두꺼운 링이 생겼습니다.
정직하게 크기를 키우는 쪽이 결과가 나아서 그렇게 했습니다.
`input`은 대체 요소라 `::after`가 신뢰할 수 없다는 점도 이유입니다.

### 의도적으로 제외한 것

- `.auth-sheet-terms a` — 문장 안에 인라인으로 들어간 링크. **WCAG 2.5.8이 명시적으로
  면제**합니다. 44px을 강제하면 문단이 깨집니다.
- `.plan-week-day` — 레이아웃 제약. 320px에서 실측하면 스트립 폭이 **266px**인데
  7×44 + 6×6px gap은 **344px**가 필요해 78px 모자랍니다. gap을 0으로 해도
  7×44=308로 여전히 넘칩니다. 44를 맞추려면 주간을 스크롤하거나 날짜를 가려야 하는데,
  한 주를 한눈에 보는 컴포넌트의 목적을 해칩니다.
  현재 33×71로 **WCAG 2.5.8 AA(24×24)는 충족**하고, AAA/HIG의 44만 미달입니다.

## 회귀 방지

`tests/e2e/core-loop-v2.spec.js`의 "actual Goal and Today paths…" 테스트가
이제 `app.html`의 `<body>` 글꼴과 `--font-body` 토큰 자체를 검사합니다.
(이전에는 프로토타입 페이지만 검사해서 이 버그가 통과했습니다.)
버그를 일부러 되살려 이 테스트가 **실패하는 것까지 확인**했습니다.
