## 판정 규칙

- **조각이 사문** := 그 조각의 클래스 중 하나라도 살아있는 집합에 없다.
  후손 셀렉터 `.home-page .pillar-grid`는 두 클래스가 모두 있어야 매치한다.
- **규칙 삭제** := 모든 콤마 조각이 사문. 하나라도 살아 있으면 손대지 않는다.
- `:not()`/`:has()`/`:is()`/`:where()` **안의 클래스로는 판정하지 않는다** —
  `:not(.foo)`는 `.foo`가 없어도 매치한다. 괄호 안까지 세었더라면 지웠을 규칙: **0개**.
- 껍데기 `@media`는 **안에 규칙이 있었는데 전부 사문이 된 것만** 지운다.
  원래부터 비어 있던 블록 2개는 건드리지 않았다.

## 삭제기의 버그를 잡았다 — 여러 줄 셀렉터의 고아 조각

첫 판은 규칙 구간의 시작을 **`{`가 있는 줄**로 잡았다. 셀렉터가 여러 줄에 걸치면
앞부분이 삭제 범위 밖에 남는다.

```css
.paid-box ul,        ← 728  남는다
.pricing-grid ul {   ← 729  여기부터 지운다
```

남은 `.paid-box ul,`가 **다음 살아있는 규칙에 들러붙어** `.app-dashboard`가
`.paid-box ul, .app-dashboard`가 됐다. 15곳에서 이 일이 벌어졌다.

**계산값 diff는 이것을 못 잡는다.** 죽은 셀렉터가 살아있는 규칙에 붙은 것뿐이라
렌더가 동일하기 때문이다. 잡아낸 것은 **규칙 셀렉터 다중집합 대조**였다 — 사라진
셀렉터가 345개인데 지운 규칙은 325개로 20개가 초과였다.

구간 시작을 **셀렉터 텍스트가 처음 나타난 줄**로 고치니 사라진 셀렉터 325개가 지운
규칙 수와 정확히 일치했다. **증거 장치를 둘 이상 두는 이유가 이것이다.**
