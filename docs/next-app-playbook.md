## 1. 첫 주에 확정할 것 — 뒤집으면 비싼 순서대로

코드를 쓰기 전에 답을 종이에 적는다. 넷 다 여기서 실제로 뒤집혔고, 넷 다 뒤집을 때 **다른 결정 여러 개를 같이 끌고 갔다.**

### ① 결제 방식 — 스토어 IAP인가 웹 PG인가

앱으로 낼 거면 **처음부터 IAP다.** 나중에 바꾸면 단가 모델 전체가 다시 계산된다.

| | 웹 PG(토스) | 스토어 IAP |
| --- | ---: | ---: |
| 수수료 | 3.3% (117원) | **15% (532원)** — 미신청/미적용이면 30% |
| 부과 기준 | 표시가 | **공급가액**(스토어가 판매자로서 부가세 직접 납부) |
| 3,900원 기준 순수익 | 3,428원 | **3,013원** |
| 총마진 목표 | 60% | **48%** |

`5d39354`에서 이 재계산을 했다. AI 예산 1,200원/월이 48% 상한까지 여유 **11원**으로 붙었다. 가격을 먼저 확정하고 나중에 수수료를 15%p 움직이면 이런 자리로 몰린다.

> **다음 앱**: 가격은 "마지막에 정하는 것"이 아니다. 수수료율을 먼저 확정하고 → 원가(AI·인프라) 상한을 정하고 → 가격을 낸다. 15%는 목표치고 확정값이 아니다(Apple Small Business 미신청 시 1년차 30%, Google 한국 적용 시점 미정) — **30%로도 음수가 아닌지 먼저 확인한다.**

**표면 규칙 하나**: 페이월과 결제는 같은 표면에 있어야 한다. 잠그는 화면과 낼 수 있는 화면이 갈라지면 유저는 막다른 길을 만난다. 웹에서 잠그고 앱에서만 결제되면 웹 유저는 나갈 곳이 없다.

### ② 무료 티어 — 만들 거면 처음부터, 아니면 아예 안 만든다

무료 티어를 만들었다가 P1에서 폐지했다(`47a02cf`). 폐지 비용은 코드 삭제가 아니라 **판정 지점 전수 점검**이었다. `free` 문자열이 어디에서 자격 판정에 쓰이는지 전부 찾아야 했고, 재발 방지로 소스 스캔 테스트를 세워야 했다.

폐지 후 남은 형태가 좋다 — 그대로 가져간다:

- **단일 상태 머신** `resolveEffectivePlan(user, now)` 하나가 모든 자격을 답한다. 판정 지점이 흩어지지 않는다.
- **상태 전이표**를 문서에 두고 테스트가 그 표를 강제한다.
- **폐지한 이름은 소스 스캔으로 막는다** (`plan-policy.test.mjs`). 식별자 스캔과 화면 문구 스캔은 **별개다** — 식별자만 보면 `admin.html`에 남은 한글 문구가 빠져나간다. 실제로 그랬다.
- 만료 후에도 **법적으로 열어야 하는 것**(내 데이터 열람·내보내기·탈퇴·결제 해지)은 페이월 뒤에 두지 않는다. 타협 불가.

### ③ AI를 코어 루프에 넣을 것인가

**넣지 않았다.** 온보딩을 AI 위저드로 만들었다가 수동 4단계 빌더로 교체했고, 그 결과 **계획 생성 AI 비용이 0이 됐다.** 유저가 직접 만들기 때문에 생성 횟수 제한도 필요 없어졌다.

교체는 한 번에 안 끝났다. 라우트를 지운 뒤 **사문 코드가 남아 별도 PR로 청소했고**(`c1f8e19`), 그 뒤에도 Durable Object 하나가 남아 또 지웠다(`2b636c0`).

> **다음 앱**: AI는 코어 루프가 **아니라** 코어 루프 위의 부가 기능으로 시작한다. 수동 버전이 쓸 만한지 먼저 보고, AI는 그 위에 얹는다. 코어 루프에서 AI를 걷어내는 비용은 얹는 비용보다 훨씬 크다 — 라우트·계약·클라이언트 경로·저장 스키마·요금제가 전부 딸려 나온다.

**AI를 얹을 때 그대로 가져갈 구조** (`docs/ai-architecture.md`):
- 클라이언트가 보낸 `plan`·가격·차감량은 **신뢰하지 않는다.** 서버가 인증된 유저 + 확정 action + 중앙 정책으로 계산한다.
- 요청마다 `requestId`로 **멱등화**한다.
- 원장은 **단일 권위**다. 폴백을 두지 않는다(§7-②).

### ④ 폰트

`--font-body`가 `Pretendard`를 가리키는데 **`@font-face`가 저장소 어디에도 없었다.** 본문 전체가 조용히 OS 기본 글꼴로 떨어졌고, 그 글꼴들은 굵기 단계가 좁아 **533개의 `font-weight` 선언 중 상당수가 화면에서 서로 구분되지 않았다.** 유저 피드백 "폰트가 눈에 들어오지 않는다"의 실체가 이것이다.

**이 버그는 한 번 "고쳐졌다"고 기록돼 있었다.** 이전 라운드에서 토큰 충돌(`--font-body: 15px`가 패밀리 토큰을 덮음)을 고치고 회귀 테스트까지 붙였다. 그 수정은 토큰 충돌만 풀었고 **폰트 파일이 없다는 사실은 건드리지 않았다.**

테스트가 못 잡은 이유가 정확하다:

```js
// 잘난체 — 실제 woff2 응답 200 + content-type + document.fonts.check 까지 본다
// 본문 폰트 — getComputedStyle(...).fontFamily 문자열만 본다  ← 실재 여부를 안 본다
```

> **다음 앱 규칙**: 폰트는 **로드를 테스트한다.** woff2 응답 200 + `content-type` + `document.fonts.check()`. `getComputedStyle().fontFamily` 문자열 비교는 0비트다(§4-③과 같은 형태). 그리고 **굵기 단계가 있는 폰트를 고른다** — 굵기가 400 하나뿐인 폰트는 "굵기로 위계를 준다"는 설계를 제목에서 그대로 무너뜨린다(고운돋움이 이 이유로 탈락했다).

## 2. 출시 시계부터 역산한다 — 코드 속도와 무관한 경로

**Google Play 개인(Individual) 계정은 비공개 테스트에 테스터 12명이 14일 연속 참여해야 프로덕션 신청이 열린다.** (2023-11 이후 생성 계정)

```
앱 생성 → 선언 전부 → 등록정보 → 비공개 테스트 업로드(심사) → 테스터 12명 옵트인
                                                              └─ 여기서 14일 시계 시작
```

**시계는 업로드한 날이 아니라 "12명이 실제로 옵트인한 시점"부터 센다.** 그래서 우선순위는 ① 심사 통과 ② 12명 모으기 둘이고, 결제 상품·RTDN 배선 같은 나머지는 그 14일 **안에** 병렬로 하면 일정에 영향이 없다.

이 프로젝트는 코드가 거의 끝난 뒤에야 이 시계를 알았다. 2026-08-06 현재 병목은 코드가 아니라 **테스터 15명과 14일**이다.

> **다음 앱 D-1일차 체크리스트**
> 1. 개발자 계정 유형 확인 (조직 / 개인) — 이 값 하나가 출시 경로를 가른다
> 2. 개인이면 **오늘부터 테스터를 모은다.** 12명은 하한, **14~15명 권장**(중간 이탈 대비). 가족·지인이 가장 확실하다
> 3. 내부 테스트(심사 없음, 즉시)와 비공개 테스트(심사 있음, 14일 인정)를 **같이 연다** — 내부는 본인 기기 검증용, 14일 요건은 비공개만 인정
> 4. 요건 숫자는 콘솔의 **「프로덕션 액세스 신청」** 화면이 맞다. 문서보다 그 화면을 믿는다
> 5. 사업자·통신판매업 신고 번호는 등록정보에 필요하다 — 리드타임이 있다

`docs/play-console-runbook.md` 452줄이 콘솔 화면 순서 그대로 답을 확정해 뒀다. **다음 앱은 이 파일을 첫날 복사한다.** (데이터 안전 답변·IARC 설문·타겟층·한국 정부 규정 문항까지 다 들어 있다)

## 4. 테스트 규칙 4개 — 통과하는 테스트와 지켜지는 불변식은 다르다

`CONTRIBUTING.md` 전문을 다음 앱에 **그대로 복사한다.** 네 규칙 전부 실제 사고에서 나왔다.

### ① 부수효과가 있는 경로는 두 불변식을 짝으로 단언한다

| 불변식 | 묻는 것 |
| --- | --- |
| **회계** | 재화가 두 번 빠지거나 두 번 들어오지 않는가 |
| **부수효과** | 바깥 세계가 두 번 움직이지 않는가 |

같은 구멍에 두 번 빠졌다. `worker-energy-ledger.test.mjs`에 "동시 요청에 한 번만 차감된다"가 있었고 통과했다 — 그 테스트는 `spent <= cost`만 봤다. 실제로는 원장이 `shouldExecute: false`를 돌려주는데 worker가 그 신호를 무시하고 **provider를 다시 불렀다.** 유저에게 공짜, 우리에게 실제 API 비용.

체험 시작 재호출은 더 나빴다 — `startAiTrial`이 `started: false`를 돌려줬는데 worker가 무시하고 원장 `reset`을 실행해 **체험 크레딧 무한 리필**이 됐다.

```js
assert.equal((await usage(ctx)).balance, spentBefore);        // 회계
assert.equal(await grantTransactionCount(ctx), grantsBefore); // 부수효과
assert.equal(providerCalls, 1);                               // 부수효과
```

**부수효과는 결과가 아니라 호출로 잰다.** 재지급과 소비가 같은 양으로 겹치면 잔량은 그대로다.

### ② 새 테스트가 실제로 결함을 잡는지 확인한다

수정과 테스트를 같이 쓸 때는 **수정을 잠시 되돌려 테스트가 실패하는 것을 눈으로 보고** 다시 적용한다. 고친 것마다 각각 한다. W2에서 다섯 가지를 각각 되돌렸고 **그중 하나가 아무도 몰랐던 문제를 드러냈다** — 그게 ③이다.

### ③ 기본값과 같은 값을 단언하는 테스트는 0비트다

```js
assert.deepEqual(normalize(legacy).dailyCheer, { key: "", celebrate: 0, comfort: 0 }); // 통과
```

**정규화 코드를 통째로 지워도 통과했다.** 기본값을 스프레드한 뒤 덮어쓰는 구조라, 정규화가 없으면 단언한 값이 그대로 남는다. 변환·정규화는 최소 세 입력으로 본다: ① 없음 → 기본값 ② **정상값 → 그대로 살아 돌아온다** ③ 망가진 값 → 안전한 값.

### ④ 상태를 통째로 다시 세우는 함수는 필드별 처분을 목록으로 선언한다

같은 형태로 **네 번** 당했다. `resetLedgerForPlan` 하나에서 셋(체험 무한 리필 / 멱등성 레코드 소멸 / 오늘 응원 부활), 그리고 원장 밖에서 하나 더 — **로그인 시 계정 스냅샷 복원이 게스트 계획을 덮어 실제 유저 데이터가 사라졌다.** 이건 **두 번 고쳤다**(처음 고친 뒤에도 승계 확인 경로에 같은 형태가 남았다).

넷 다 "복원·리셋이 **무엇을 덮고 무엇을 남기는가**"를 아무도 명시적으로 답하지 않아서 생겼다. 저장소가 원장이든 `localStorage`든 같다.

> 구현: `energy-ledger.mjs`의 `RESET_DISPOSITION` + `energy-ledger-reset.test.mjs`. 테스트가 목록의 **망라성과 정확성을 둘 다** 강제한다 — 새 필드가 등록되지 않으면 실패하고, 라벨과 실제 동작이 어긋나도 실패한다.
> **다음 앱은 클라이언트 스냅샷 쪽에도 같은 목록을 만든다.** 여기는 끝까지 없었고, 그래서 네 번째가 났다.

### 규칙 ⑤ (다음 앱에서 추가) — 존재를 단언하지 않는 테스트를 만들지 않는다

`today.spec.js`의 `.ghost-link` 단언은 **그 요소가 DOM에 없어서 `toBeHidden()`이 항상 통과**하고 있었다. 사문 CSS 청소 때 CSS와 함께 지웠다. `toBeHidden()`·`not.toBeVisible()` 계열은 **먼저 존재를 단언**하고 쓴다.

## 5. 실기기·외부 시스템 — 대체 불가능한 것

### ① 스파이크는 "확인 불가능한 것"에 결론을 걸지 않는다

`docs/capacitor-spike.md`는 실기기 없이(이 머신에 Java·Android SDK·Gradle이 없다) 조사만으로 **가설 A를 기각했다.** 근거 셋을 코드와 Capacitor 소스로 세웠다:

| 블로커 | 스파이크 판정 | 실기기 결과 |
| --- | --- | --- |
| ① 상대 경로가 서버에 안 닿는다 | 기각 근거 | **해소** — 절대 URL + `apiUrl()` |
| ② 절대 URL로도 403 | 기각 근거 | **해소** — `CapacitorHttp`는 `Origin`을 안 붙인다 |
| ③ 쿠키를 주입해도 안 붙는다 | 기각 근거 | **해소** — 네이티브 잼이 cross-site로 실어 준다 |

**셋 다 뒤집혔다.** 스파이크는 "보안 자세를 두 군데 바꿔야 한다(동일출처 → 허용목록, `SameSite=Lax` → `None`)"고 경고했는데, **실제로는 하나도 바꾸지 않았다.** 서버 변경 0곳으로 구성 C가 성립했다.

스파이크 자체는 잘 쓰였다. **`[코드]` / `[CAP]` / `[미검증]` 표기로 근거 등급을 나눴고, §5에 "실기기 없이 확인 불가능한 것" 6개를 모아 두고 "§2의 결론은 첫 두 항목에 달려 있다"고 명시했다.** 그 표기가 있었기 때문에 실기기 회차에서 무엇부터 재야 하는지가 정해져 있었다.

> **다음 앱 규칙**: 스파이크 결과 문서는 **근거 등급 표기를 의무화**한다. 그리고 미검증에 매달린 결론은 **결론이 아니라 가설로 적는다.** "리드타임 추정은 하지 않는다 — 1번이 미검증인 상태에서 낸 숫자는 근거가 없다"고 적은 것이 옳았다.

### ② 실기기 회차는 대조군을 걸어야 무언가를 증명한다

3회차에서 쿠키가 실린다는 것을 잰 방법이 정확하다:

- 실서버 페이지에서 `/api/auth/me`를 물으면 **동일 출처라 아무것도 증명하지 못한다.** 번들 페이지(`https://localhost/app.html`)로 **되돌린 뒤** 물었다.
- 방금 이동의 잔상일 수 있으므로 `am force-stop`으로 죽이고 다시 띄워 같은 답을 확인했다.
- 로그인 provider가 앱 안에 남았는지는 **화면이 아니라 `dumpsys`의 최상위 액티비티**로 판정했다.
- 측정 방법 자체를 정정한 적도 있다 — `find /sdcard`는 파일이 있어도 못 찾는다.

### ③ 외부 시스템의 지연을 코드 문제로 오진하지 않는다

결제 검증 502의 원인은 **서비스 계정 권한 전파 지연**이었다. 콘솔 설정은 처음부터 맞았고 코드는 한 줄도 안 고쳤다 — **권한 부여 4분 뒤에는 403, 8시간 뒤에는 성공.**

> **다음 앱**: Google Cloud/Play 권한을 새로 부여했으면 **최소 하루 기다린 뒤에 디버깅을 시작한다.** 그 전의 403/502는 신호가 아니다.

### ④ 상태 점검이 "준비됐는가"를 답하게 한다

`binding-health.mjs` + `scripts/verify-deployed-bindings.mjs`가 **배포된 워커가 실제로 해석한 바인딩**을 세 경로 모두의 마지막 관문으로 삼는다. 설정 파일이 아니라 배포 결과를 본다. 그대로 가져간다.

## 6. 개발 환경 함정 — Windows + 병렬 worktree

전부 여기서 실제로 시간을 잡아먹었다. 다음 앱 첫날 `.claude/settings.json`과 README에 박아 둔다.

| 함정 | 증상 | 대처 |
| --- | --- | --- |
| **Bash PATH가 깨져 있다** | 기본 명령이 안 잡힌다 | 모든 Bash 호출 앞에 POSIX PATH를 export한다 |
| **PowerShell 도구가 멈춘다** | `Write-Output`에서 타임아웃 | 재시도하지 말고 Bash로 갈아탄다 |
| **worktree e2e 포트 충돌** | 다른 worktree를 조용히 테스트한다 | `PORT=`를 넘긴다. PR #68 이후 겹치면 **크게 실패**한다 |
| **`git stash`가 worktree 간 공유** | 병렬 세션의 pop이 내 worktree에 떨어진다 | A/B 비교는 stash 말고 **파일 복사**로 한다 |
| **Windows worktree 삭제 실패** | `Permission denied` | `attrib -R` → `rm -rf` → `git worktree prune`. squash 머지 뒤엔 `--is-ancestor`가 거짓말한다 |
| **Git Bash `curl` 한글 body** | CP949로 깨져서 전송된다 | node `fetch`로 프로브한다 |
| **날짜 의존 e2e 픽스처** | 주말·월 경계에서만 깨진다 | `everyDay: true`. `setFixedTime`을 반사적으로 쓰지 않는다 |
| **e2e 3-worker 부하 취약** | 로컬 장비에서 산발 실패 | `--last-failed --workers=1`로 트리아지 |
| **인증 게이트 뒤 페이지 측정** | `/admin.html`이 세션 없이 리다이렉트돼 **엉뚱한 페이지를 잰다** | 측정 전에 최종 URL을 확인한다 |
| **안드로이드 실기기 QA** | 케이블이 충전 전용, 백그라운드에서 측정이 조용히 멈춘다 | 무선 adb + CDP eval, 앱을 포그라운드에 유지 |
| **"앱에서 나갔다 돌아옴" e2e 재현** | bfcache는 `no-store`라 절대 안 걸린다 | 내비게이션을 **204로 완료**시킨다 (abort/hang/`location.assign` 패치는 전부 실패) |

### 배포 게이트를 오해하지 않는다

**`production.yml`이 `push: branches: [main]`이다. main 머지가 곧 프로덕션 배포다.** 승인 단계도 대기도 없다. 문서 여러 곳이 "Staging 인수 → Production 승인" 절차를 전제로 쓰여 있지만 배선은 자동이다. 이걸 몰라 **파괴적 Durable Object 마이그레이션이 이미 나간 뒤에 "아직 배포 안 했다"고 보고한 적이 있다.**

> **다음 앱**: 배포 게이트는 **머지 전 CI**다. 되돌릴 수 없는 마이그레이션이 걸려 있으면 **머지 자체가 그 결정이다.** 그리고 Staging이 Production보다 뒤처져 있는 게 정상이다(dispatch 전용).

## 7. 설계 결정 중 그대로 가져갈 것

### ① 디자인 토큰은 단일 레이어 + 역할 이름

`--font-weight-title` 같은 **역할 토큰**으로 옮기고, 리터럴로 남길 곳(글리프 등)은 **사유를 주석으로 적었다.** 그리고 **잔여 수 래칫 테스트**를 세웠다 — 계약 테스트가 못 잡는 신규 유입을 막는다. 이게 없으면 이관이 끝나자마자 다시 샌다.

### ② 원장은 단일 권위 — 폴백을 두지 않는다(fail-closed)

차감 경로의 KV 폴백을 없애고 Durable Object를 유일한 권위로 만들었다(`db5e760`). 폴백이 있으면 **폴백 경로에서 불변식이 조용히 깨진다.**

- 하루 상한 같은 **카운터도 원장 안에** 둔다(`d77e851`) — 밖에 두면 리셋과 함께 부활한다
- 체험 지급은 **회차 키로 멱등화**하고 blunt reset에서 분리한다(`5740ea8`)
- KV read-modify-write가 남은 곳은 **부채로 명시**해 둔다

### ③ 삭제를 미루지 않는다 — 미루면 삭제 자체가 위험 작업이 된다

6개월 뒤 사문 CSS를 지울 때 **위험이 두 개 나왔다:**

**교훈 1 — 클래스 이름은 런타임에 조립된다.** 문자열 검색이 사문이라 판정한 150개 중 **6개가 살아 있었다.** `` `task-row task-${period.theme}` `` 같은 조립 때문이다. 조립 지점 전수 목록을 `docs/artifacts/dead-css-live-set.md`에 남기고, 새 조립 지점을 만들면 거기에 추가하게 했다.

**교훈 2 — 증거 장치를 둘 이상 둔다.** 첫 삭제기가 여러 줄 셀렉터의 앞부분을 고아로 남겨 다음 규칙에 들러붙였다(15곳). **죽은 셀렉터가 붙은 것뿐이라 렌더가 동일해 계산값 diff는 0이었다.** 잡아낸 것은 **규칙 셀렉터 다중집합 대조**다. 같은 버그가 이전 PR에도 있어 main에 흔적 7곳을 남겼다.

> **다음 앱**: 대규모 삭제는 **직교하는 증거 장치 2개**를 세운다(계산값 스냅샷 diff + 규칙 다중집합 대조). 하나는 반드시 다른 하나가 못 보는 것을 본다. 도구는 `scripts/snapshot-computed-styles.cjs`에 있다.
> **그리고 애초에 이 작업이 필요 없게 한다** — 기능을 지울 때 CSS·테스트·라우트를 **같은 PR에서** 지운다.

### ④ 페이월·자격 판정은 문자열 비교로만, 판정 지점은 표로

"PRO 전용" 판정을 계산이 아니라 **문자열 비교**로만 한다. 그리고 판정 지점 전체를 표로 남기고 테스트가 그 표를 강제한다.
