## 우선순위별 개선

### 1. 데이터 보안 신고 재검토 — 정확성 우선

[공개 데이터 보안](https://play.google.com/store/apps/datasafety?id=com.olivenrich.onmyway&hl=ko&gl=KR)은 개인정보·구매 내역·사용자 제작 콘텐츠를 **공유**한다고 하면서 **수집된 데이터 없음**을 표시한다. 한편 [공개 개인정보 처리방침](https://onmyway.olivenrich.com/privacy.html)에는 회원 정보와 목표·계획·실행 정보의 서버 저장이 명시돼 있다. 소스에서도 `script.js:352`의 동기화 목록, `auth-service.mjs:1131`의 상태 저장, `auth-service.mjs:1781`의 KV 저장을 확인했다.

Google은 기기 밖 전송을 수집으로 정의한다. 서비스 제공자에게 맡긴 처리는 공유 예외가 될 수 있지만, 수집까지 사라지는 것은 아니다. 일시 처리도 양식에는 포함하며 정해진 조건을 충족할 때 공개 표시에서 제외한다. 서버에 저장되는 계정·목표 정보를 일시 처리로 볼 근거는 없다. [Google 공식 정의](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

따라서 현재 신고와 동작 간 불일치 가능성이 높다. Console에서 수집/공유 선택값을 데이터 유형별로 다시 검토해야 한다. 두 칸이 뒤바뀌었을 가능성은 있지만 내부 제출값을 보지 않았으므로 원인으로 확정하지 않는다. 업체명만으로 모든 외부 처리를 수탁 예외로 확정하지 않는다. AI 요청 전송, 공급자 보존 설정·계약, 구매 처리 및 로그 보존을 포함해 확인한 뒤 제출한다. 위반 판정이나 제재가 발생했다는 의미는 아니다.

기존 `play-store-submission.md`의 대화 로컬 저장 → 수집 아님이라는 추론과 외부 업체의 수탁 관계 일괄 판정은 그대로 재사용하지 않는다. 대화 이력의 저장 위치와 AI 요청 내용의 외부 전송은 별개다. 공개 방침의 토스 중심 결제 설명과 결제 활성화 전이라는 문장도 현재 Play Billing 운영과 함께 검토할 항목이다.

로컬 `brand/store/`의 새 8장은 게시되지 않았다. 전면 재제작보다 기존 새 이미지 중 7장을 활용한다. 추천 순서는 아래와 같다.

### 3. ‘새로운 기능’의 자동 생성 약속 수정 — 확정된 불일치

현재 출시 안내는 목표를 AI가 실행 계획으로 자동 변환한다고 설명하지만 본문과 현행 온보딩은 사용자가 계획을 만들고 확정하는 구조다. AI는 이후 다듬기·회복·일정 재조정을 돕는다. 아래 대체 문안을 준비했다. 현재 새 기능을 추가했다는 주장은 넣지 않았다.

### 4. 짧은 설명을 사용자의 문제와 연결 — 검증할 메시지

현재 짧은 설명은 기능상 틀리지 않지만 계획 작성 절차가 먼저 나온다. ‘계획이 밀린 뒤 다시 시작’이라는 이득을 앞세우는 후보를 아래에 작성했다. 이름의 키워드 추가나 한글명 변경이 검색 순위를 높일 것이라고 단정하지 않는다. 우선 기존 앱 이름을 유지한다.

### 5. 체험 조건을 구체적으로 표시 — 정보 누락 보완

현재 상세 설명은 카드가 필요 없고 Pro가 월 3,900원이라는 점을 알린다. 그러나 **가입 다음 날 23:59 KST 종료, 체험 15크레딧, 다이어리 북 제외, 체험 후 자동 결제 없음, 별도 Pro 구독의 자동 갱신**은 충분히 구분하지 않는다. 기능을 바꾸기 전에 설명을 실제 조건에 맞추는 것이 우선이다. 짧은 체험이 설치·재방문에 미치는 영향은 별도 측정할 가설이다.

- 미실행: Play Console 저장·심사 제출·공개 반영. 앞선 연결 계정들은 기존 개발자 앱 목록 대신 가입 화면을 표시했고 올바른 개발자 계정 접근은 아직 확인되지 않았다.
- 미확인: 스토어 방문자·설치 버튼 클릭·실제 신규 설치·국가별 배포 설정·Android vitals. 공개 `10+`만으로 진단하지 않는다.
- 접근이 확보되면 최근 7일/28일을 국가·신규 사용자·유입 경로별로 나눠 본다. 방문 자체가 적으면 유입 경로, 방문 대비 설치 의향이 낮으면 메시지·이미지, 의향 대비 실제 설치가 낮으면 설치 가능성과 기기 조건을 확인한다. 설치 후 첫 기록이 적으면 첫 사용 흐름을 별도로 검토한다.
- 현재 Google 문서는 등록정보 보고서의 설치 의향 클릭과 실제 획득을 구분한다. 두 값을 같은 설치 전환으로 보고하지 않는다. [Google 성과 지표 안내](https://support.google.com/googleplay/android-developer/answer/9859173?hl=en)
- 이번에는 문서와 로컬 업로드 지침만 정리했다. 제품 코드·체험 기간·가격·스토어 상태를 변경하지 않았고 제품 테스트도 실행하지 않았다.
