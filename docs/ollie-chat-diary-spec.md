## 2. 화면 흐름 (v1과 동일한 골격)

- 진입: 기록 탭 "올리와 이야기하기" + 오늘 탭 치어링에서 "이야기 이어가기"
- 채팅 시트: 말풍선 히스토리(오늘), 에너지 잔량 상시 표시, 메시지 1건 = 에너지 1, 빠른 시작 칩 4종
- AI 실패 시 자동 환불(서버 내부 처리) + 재시도 안내
- 소진 시: 세션당 1회만 충전 안내. 죄책감 유발 문구 금지, 가격·구성 명시
- 다이어리 통합: 그날의 감정 기록 + 대화 로그 = 하나의 "하루 페이지"

## 3. 에너지 원장 서버 이전 설계 (C1 — 확정안)

### 원칙
에너지가 유료 재화가 되는 순간 브라우저 저장(localStorage) 원장은 폐기한다. **잔량의 진실은 서버에만 있고, 클라이언트는 표시용 캐시**다.

### 구조
- **저장소: 유저별 Durable Object `EnergyLedger`** (id = 유저 id, SQLite storage). 이미 운영 중인 DO 인프라(GuestPlanDraftObject)와 동일 패턴이라 신규 학습 비용이 없다. DO는 유저당 단일 실행이 보장되어 두 기기 동시 사용에도 이중 차감이 없다.
- **원장 방식: append-only 거래 기록** — `{ type: grant|spend|refund|purchase, amount, reason, txnId, at }` + 잔량 캐시. 원장 자체가 CS 분쟁 대응용 감사 기록이 된다.
- **월간 충전은 lazy-grant**: 매달 첫 요청이 들어올 때 "이번 달 grant 기록이 없으면 300 지급". 유저별 크론이 필요 없다.

### 핵심 설계 결정 — 차감은 클라이언트가 요청하지 않는다
`/api/energy/spend` 같은 차감 API를 만들지 않는다. **에너지가 드는 AI 라우트(companion-chat 등)가 서버 내부에서 차감 → AI 호출 → 실패 시 스스로 원복**하고, 응답에 최신 잔량을 담아 내려준다. 클라이언트가 만질 수 있는 건 조회(`GET /api/energy`)뿐이므로 조작 가능한 표면이 아예 없다. 환불 API도 외부에 열지 않는다.

### 결제(팩 충전)
- Toss 단건 결제 → 승인 콜백에서 **orderId 멱등 처리** 후 `purchase` 기록. 같은 콜백이 두 번 와도 한 번만 충전.
- 팩 유효기간: **구매 후 1년** (전자상거래법상 표시 필요 — 하단 정책 프레임 참조, 최종 문구는 법무 확정)

### 마이그레이션
지금이 이전의 적기다 — **아직 돈 주고 산 에너지가 없기 때문**이다. 기존 유저의 로컬 잔량은 신뢰하지 않고 서버가 플랜 기준으로 재부여한다(체험 10, PRO 당월 300). 팩 판매 시작 전에 반드시 완료한다.

## 4. 다이어리 북 — 기록 보관과 소장 (창업자 아이디어 구체화)

### 컨셉
한 달의 기록(감정·한 줄 기록·올리와의 대화·완료 통계)을 **"올리 다이어리 북"** 한 권의 PDF로 만들어 소장하게 한다. 표지와 본문에 올리 일러스트, 올리가 쓴 머리말(그 달의 여정 요약)과 마지막 장의 올리 편지(AI 생성)가 들어가 소장 가치를 만든다.

### 보관 정책과의 연결 (결정)
- 무료: 원본 로그 **90일 보관**. 만료 임박 시 "다이어리 북으로 만들어 간직하세요" 안내 → 북 생성 후 원본 정리 동의. 유저는 데이터를 잃지 않고, 우리는 저장 비용과 개인정보 보유를 최소화한다.
- PRO: **구독 기간 동안 전체 보관** + **매월 다이어리 북 1권 무료 자동 제공** ("매달 올리가 지난달 이야기를 책으로 만들어드려요" — 구독 유지의 감성적 이유가 된다)
- 북 생성 비용: **에너지 10** (AI 호출은 머리말 + 편지 2회 수준). 과거 달 소급 생성·재발급도 동일.

### 전달 방식 (기술 현실 반영)
- **카카오 알림톡은 파일 첨부가 불가**하다. 알림톡은 "다이어리 북이 준비됐어요" 알림 + **서명된 만료 링크(7일)** 로 전달한다.
- 이메일은 첨부 대신 동일한 만료 링크 방식으로 통일한다 — 민감한 기록이 담긴 PDF를 평문 첨부로 보내지 않는 것이 안전하다.
- 기본 경로는 **앱 안에서 즉시 다운로드**. 발송(알림톡/이메일)은 선택 옵션.
- PDF 생성 위치: 텍스트(머리말·편지)만 서버 AI로 만들고, **조판·PDF 변환은 클라이언트(인쇄용 레이아웃 → PDF 저장)** 에서 한다. Workers에서 무거운 PDF 렌더링을 피해 서버 비용을 0에 가깝게 유지하고 디자인 자유도를 확보한다.

## 5. PRO 대화 한도 (결정: 월 300 유지, 무제한 없음)

권고를 확정한다: **PRO = 매월 에너지 300, 이월 없음, 소진 시 팩 구매.**

근거: ① 300은 하루 평균 10턴 — 정상 사용자에겐 체감상 무제한이면서 유저당 AI 원가가 월 예산(1,000원) 안에 수학적으로 갇힌다. ② "무제한"은 봇·프롬프트 남용의 표적이 되고 원가 상한이 사라져 2,900원 구조가 깨진다. ③ 300을 다 쓰는 헤비 유저는 불만 유저가 아니라 **가장 팩을 살 확률이 높은 유저**다 — 무제한은 이 매출을 스스로 지우는 선택이다. ④ 추후 사용 데이터가 쌓이면 상위 티어(예: PRO+ 월 4,900원 / 에너지 700) 실험 여지를 남긴다 — 지금은 만들지 않는다.

## 6. 대화 품질·안전 지침 (v1과 동일)

컨텍스트(목표·완료율·놓친 일정·연속일·최근 감정 + 최근 6턴), 목표·실행 중심 대화, 혼내지 않기. 올리는 친구이지 상담사·의사가 아니며, 위기 신호(자해·극단 표현) 감지 시 공감 후 전문가·주변 도움을 안내하는 고정 응답(에너지 미차감). 미성년 이용 감안.

**말투는 캐릭터 바이블 §7을 프롬프트에 이식한다**: 짧고 솔직하게, 부드러운 존댓말 + 혼잣말, 핵심 문장은 두 문장 25자 안팎, 훈계 금지("열심히 해야지" 계열), 감정 경시 금지("별일 아니야"), 올리 세계의 의성어(둥실·톡·뭉게·쪼르르·파닥)를 선택적으로. 모든 답을 위로로 끝내지 않고 장난·머쓱함·엉뚱한 관찰을 섞는다. 성별 대명사는 쓰지 않는다(미확정 설정).

## 6-1. 대화 감정 연출 시스템 — "말풍선이 아니라 올리가 대답한다"

### 원리 (캐릭터 바이블 v0.2를 앱에 그대로 적용)

바이블의 핵심 원리가 앱 구조와 정확히 맞물린다:

| 바이블 | 앱 |
| --- | --- |
| **구름 = 순간 감정** (즉시 변함) | 이번 대화 턴의 올리 표정·모션 |
| **올리브나무 = 누적된 마음** (오래 지속되면 변함) | 연속 실행일·완료율·관계 XP가 만드는 나무 상태 |
| 감정을 잘 지나온 날 열매가 맺힘 | 다이어리를 남긴 날의 보상 연출 (v2, 열매 디자인 확정 후) |

### 구현 — AI 응답에 감정 태그 추가

companion-chat 응답 스키마를 `{ headline, reply, emotion }`으로 확장한다. `emotion`은 바이블 감정표 15종 중 **대화 v1에서는 8종의 enum**으로 제한한다(스키마 strict 검증):

`평온 · 기쁨 · 뿌듯함 · 슬픔공감 · 피곤위로 · 불안공감 · 부끄러움 · 결심`

클라이언트는 `emotion → { 표정 이미지, 모션 클래스 }` 매핑 테이블 하나로 처리하고, 알 수 없는 값은 평온으로 폴백한다.

### 연출 계층 (비용 낮은 순서로 구축)

- **L1 · 모션 (에셋 불필요, CSS만)**: 상시 둥실거림(부유), 응답 대기 중 "올리가 생각하는 중…" 뭉게구름 점 3개, 감정별 모션 프리셋 — 기쁨은 통통 튀기, 슬픔·피곤은 살짝 가라앉기, 불안은 잔떨림, 부끄러움은 구름이 **더 부풀기**(바이블: 숨으려 할수록 커진다), 뿌듯함은 반짝. 큰 모션 뒤에는 잎 한 장·물방울 같은 **잔여 반응**을 남긴다(바이블 §6).
- **L2 · 표정 (정지 이미지 8종)**: emotion 태그에 따라 채팅 시트의 올리 이미지가 바뀐다. 유저 메시지 전송 순간 올리가 살짝 기울어 "듣는" 자세 연출.
- **L3 · 나무 반응 (에셋을 구름/나무 레이어로 분리 제작한 뒤)**: 나무가 올리보다 **반 박자 늦게** 반응(바이블 §6 — CSS 딜레이로 구현). 올리는 슬픈데 나무는 비를 좋아하는 "엇갈린 반응"이 이 캐릭터 귀여움의 핵심이므로, 분리 레이어 확보 시 최우선 구현.
- **L4 · 누적 연출 (v2)**: 연속 실행일·다이어리 작성이 나무의 잎 상태·열매로 누적 표현. 바이블 미확정 항목(#8 나무의 종, #9 열매 디자인, #10 성장 30단계)이 확정된 뒤 진행.

### ⚠ 에셋 정합성 — 지금 결정이 필요한 발견

**앱에 현재 들어 있는 올리 이미지 4종은 마케팅 캐릭터 바이블 이전의 디자인일 가능성이 높다.** 바이블·디자인 스펙 기준(크기가 다른 3~5개 덩어리 구름, 우측 어깨 위 테라코타 화분의 나무 — 구름 높이 70%, 벙어리장갑형 팔, 민트 잎 `#B8DCDC`)과 대조해 다르면, **마케팅 Phase 4(앱 공개) 때 인스타의 올리와 앱 속 올리가 다른 캐릭터가 되는 사고**가 난다. 대화 연출용 표정 8종 제작을 겸해 앱 전체 올리 에셋을 새 디자인 기준으로 통일하는 작업을 별도 트랙(디자인)으로 진행할 것. 미확정 항목(성별 대명사, 열매)에 걸리는 연출은 피한다.

## 7. 개인정보 정책 프레임 (법무 최종 검토 전제 초안)

> 아래는 개발·정책 설계용 골격이다. 처리방침·약관의 최종 문구와 법적 판단은 대표(변호사) 검토로 확정한다.

1. **수집 항목과 동의**: 대화 내용·감정 기록은 대화 기능 **최초 사용 시점에 별도 고지·동의**로 받는다(약관 포괄 동의에 묻지 않음). 감정·심리 기록은 개보법상 민감정보(건강정보)에 준할 수 있으므로 보수적으로 별도 동의 체계를 권장.
2. **AI 처리 고지**: 대화가 응답 생성 목적으로 외부 AI 처리자(OpenAI)에 전송됨을 명시한다(저장 안 함 설정 사용 중이라는 사실 포함). 이는 처리 위탁·국외 이전 고지 항목이다.
3. **국외 보관 고지**: 서버 저장소(Cloudflare)의 국가·업체·항목·보유 기간을 처리방침에 명시.
4. **보유·파기**: 무료 90일 / PRO 구독 기간. **탈퇴 시 대화 로그·다이어리·에너지 원장·서버 동기화본을 지체 없이 파기**하고, 발급된 다이어리 북 다운로드 링크를 즉시 무효화한다. 유저에게 부분 삭제 기능(특정 날짜 기록 삭제)을 제공한다.
5. **운영자 열람 금지 원칙**: 관리자 도구에서 대화 원문을 열람하지 않는 것을 내부 정책으로 명문화하고 처리방침에 밝힌다 — 신뢰가 이 기능의 전제 자산이다.
6. **연령**: 약관에 만 14세 이상 이용 명시(소셜 로그인 기반 현실적 최소선).
7. **발송 위탁**: 알림톡·이메일 발송 업체는 처리 위탁 고지 목록에 추가.

## 8. 비용 가드레일·지표 (v1과 동일 + 추가)

- 입력 ≤ 약 2,000토큰(상황 요약+6턴), 출력 ≤ 700토큰, 레이트리밋 재사용
- 추가 지표: 다이어리 북 생성률, 북 생성 유저의 이후 30일 유지율, 만료 안내 → 북 전환율
